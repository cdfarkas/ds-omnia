# ADR 0006 — Accessibility floor: WCAG 2.1 AA (EU legal baseline)

## Status

Superseded by ADR 0026

## Context

Accessibility must be a gate, not an afterthought, and it must hold across both skins — a pixel-art
skin is exactly where contrast is likely to slip. The system also needs a defensible, concrete floor
rather than a vague "be accessible".

The European Accessibility Act references **EN 301 549 v3.2.1**, which maps to **WCAG 2.1 AA** — a
clear legal baseline for the EU. axe can compute contrast from CSS, giving a deterministic result
across operating systems.

## Decision

The floor is **WCAG 2.1 AA**. The a11y addon runs with **`a11y.test: 'error'`** (a violation fails
the run) across **every theme and skin, pixel included** — the pixel palette is chosen to meet 4.5:1
contrast. **WCAG 2.2 rules run as `'warn'`** (surfaced, not blocking).

## Consequences

- Accessibility regressions fail CI, in every theme/skin combination.
- The pixel palette is constrained by the 4.5:1 requirement — a design input, not a free choice.
- Because axe derives contrast from CSS, the gate is deterministic across Windows local and Linux CI,
  not render-flaky.
- If the Phase-1 slice shows the pixel skin cannot meet 2.1 AA, this ADR and the pixel-skin scope are
  revisited (the plan's falsification condition).

## Amendment — 2026-10-30

The gate failed only on axe violations, so two kinds of real 2.1 AA failure passed it: axe
**incomplete** ("needs review") results were ignored, and axe does not test **SC 1.4.11 non-text
contrast** at all. The Input's invalid border shipped at 2.42:1 in dark+pixel that way.

- An axe incomplete result now fails a story test (`.storybook/vitest.setup.ts`), like a violation.
- A token-level test (`src/styles/contrast.test.ts`) asserts, in all four theme×skin modes, 3:1 for
  the boundary and indicator tokens and 4.5:1 for placeholder text against the page background.

Both run inside `pnpm test`. Thresholds are never loosened and axe rules are never disabled to pass.
