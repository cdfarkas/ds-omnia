# Icon

<Localized
  en={
    <>
      <p>
        The <strong>Icon</strong> atom draws one inline SVG glyph from a fixed v1 set (
        <code>github</code>, <code>linkedin</code>, <code>bluesky</code>, <code>sun</code>
        , <code>moon</code>, <code>arrow-up-right</code>, <code>arrow-down</code>), chosen
        with the <code>glyph</code> prop. Every glyph is a solid single-colour shape on
        one <code>0 0 24 24</code> grid, filled with <code>currentColor</code>, so the
        icon follows the surrounding text colour and reskins across the light/dark theme
        and neutral/pixel skin axes with no change to its own CSS.{' '}
        <code>--omnia-icon-color</code> overrides the colour through a semantic token.
      </p>
      <p>
        Size follows the text by default (<code>1em</code>). Pass <code>variantSize</code>{' '}
        (<code>sm</code> / <code>md</code> / <code>lg</code> → 1 / 1.5 / 2rem) for a fixed
        size — <code>size</code> is a native HTML name, so the axis is renamed (ADR 0015).
      </p>
      <p>
        Icons are <strong>decorative by default</strong>: with no label the atom sets{' '}
        <code>aria-hidden="true"</code> and no role, so a screen reader ignores it — the
        usual case for an icon inside a labelled <code>Button</code> or <code>Link</code>.
        Passing <code>aria-label</code> or <code>aria-labelledby</code> makes the icon
        meaningful (<code>role="img"</code>, <code>aria-hidden</code> dropped) per WCAG
        1.1.1. The label is the caller's, so no localised string ships with the atom.
        There is no <code>color</code>, <code>title</code>, <code>width</code>/
        <code>height</code> or custom-children prop: a clickable icon is a{' '}
        <code>Button</code> or <code>Link</code> wrapping an <code>Icon</code>.
      </p>
    </>
  }
