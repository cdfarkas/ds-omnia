# Textarea

<Localized
  en={
    <>
      <p>
        Use <strong>Textarea</strong> for text that runs over several lines — a comment, a
        message, a description. It is the bare field: the label, hint and error message go
        around it.
      </p>
      <ul>
        <li>
          <strong>Always give it a name.</strong> Wrap it in <code>FormField</code>, or
          pair it with a <code>&lt;label htmlFor&gt;</code> or an <code>aria-label</code>.
          A placeholder is never a label.
        </li>
        <li>
          <strong>A native textarea, with no wrapper.</strong> Every prop reaches it,{' '}
          <code>className</code>, <code>style</code> and <code>ref</code> included.
        </li>
        <li>
          <strong>
            Set the height with <code>rows</code>.
          </strong>{' '}
          Match it to the text you expect; the browser shows two lines without it. A
          longer text scrolls inside.
        </li>
        <li>
          <strong>Users resize it, and its parent sets the limit.</strong> The box fills
          the width of its parent. The handle drags both axes, down to one line high and{' '}
          <code>6rem</code> wide. A read-only field keeps the handle; a disabled field has
          none.
        </li>
        <li>
          <strong>Three sizes.</strong> <code>variantSize</code> sets the scale, from{' '}
          <code>sm</code> to <code>lg</code>; it is the same scale as Input. It changes
          the text and the padding, not the number of lines.
        </li>
        <li>
          <strong>An invalid look, no validation.</strong> <code>invalid</code> marks the
          field invalid for assistive technology and draws a danger border. Pair it with
          an error message in text.
        </li>
        <li>
          <strong>States show without colour alone.</strong> Focus draws a ring around the
          field. Outside the pixel skin the shadow grows on hover and focus; unlike Input,
          the field itself never moves, so the handle stays under the pointer. Disabled
          and read-only stay flat, and a disabled field adds a dashed border.
        </li>
      </ul>
    </>
  }

### <Localized en="Resize limits" fr="Limites du redimensionnement" />

<Localized
  en={
    <ul>
      <li>
        <strong>Width.</strong> A block, a flex container, <code>Stack</code> or{' '}
        <code>FormField</code> that has a width of its own stops the drag.{' '}
        <code>Grid</code> does too, as long as its columns fit.
      </li>
      <li>
        <strong>A CSS grid needs</strong> <code>minmax(0, 1fr)</code>{' '}
        <strong>columns.</strong> An <code>auto</code> or <code>1fr</code> column grows
        with a Textarea placed in it.
      </li>
      <li>
        <strong>A parent sized by its content does not stop the drag.</strong>{' '}
        <code>width: fit-content</code> is one; a <code>FormField</code> inside{' '}
        <code>{'<Stack alignItems="start">'}</code> is another, until you give it{' '}
        <code>width: 100%</code>.
      </li>
      <li>
        <strong>Height.</strong> It is free until the direct parent has a definite height.
        Put that height on the <code>FormField</code> itself: a height further up does not
        reach the box. A CSS grid, <code>Grid</code> included, also needs a{' '}
        <code>minmax(0, 1fr)</code> row.
      </li>
      <li>
        <strong>Room for a label.</strong> A block stops the box at its whole height, so a
        label above pushes it past the edge. A flex column (<code>Stack</code>,{' '}
        <code>FormField</code>) stops it at the room left.
      </li>
      <li>
        <strong>
          <code>max-height</code> alone
        </strong>{' '}
        stops the drag only on a flex column that directly holds the box. A block, a flex
        row and <code>Grid</code> let it overflow: use a definite height, as above.
      </li>
    </ul>
  }
  fr={
    <ul>
      <li>
        <strong>Largeur.</strong> Un bloc, un conteneur flex, <code>Stack</code> ou{' '}
        <code>FormField</code> qui a sa propre largeur arrête la poignée.{' '}
        <code>Grid</code> aussi, tant que ses colonnes tiennent.
      </li>
      <li>
        <strong>Une grille CSS demande des colonnes</strong> <code>minmax(0, 1fr)</code>.
        Une colonne <code>auto</code> ou <code>1fr</code> grandit avec le Textarea placé
        dedans.
      </li>
      <li>
        <strong>Un parent dimensionné par son contenu n'arrête pas la poignée.</strong>{' '}
        C'est le cas de <code>width: fit-content</code>, et d'un <code>FormField</code>{' '}
        dans <code>{'<Stack alignItems="start">'}</code> tant qu'il n'a pas{' '}
        <code>width: 100%</code>.
      </li>
      <li>
        <strong>Hauteur.</strong> Elle est libre tant que le parent direct n'a pas de
        hauteur définie. Donnez cette hauteur au <code>FormField</code> lui-même : une
        hauteur posée plus haut n'atteint pas le champ. Une grille CSS, <code>Grid</code>{' '}
        compris, demande aussi une ligne <code>minmax(0, 1fr)</code>.
      </li>
      <li>
        <strong>La place d'un libellé.</strong> Un bloc arrête le champ à toute sa
        hauteur, et un libellé au-dessus le pousse alors hors du bord. Une colonne flex (
        <code>Stack</code>, <code>FormField</code>) l'arrête à la place restante.
      </li>
      <li>
        <strong>
          <code>max-height</code> seul
        </strong>{' '}
        n'arrête la poignée que sur une colonne flex qui contient directement le champ. Un
        bloc, une ligne flex et <code>Grid</code> le laissent déborder : utilisez une
        hauteur définie, comme ci-dessus.
      </li>
    </ul>
  }
